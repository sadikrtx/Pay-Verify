# Prompt A1 — PayVerify BD UPGRADE: Single-Owner → Multi-tenant (Selling) Design

Upgrade the existing "PayVerify BD" web app from a single-owner system to the multi-tenant platform design below. This is an UPGRADE of the running app, not a rebuild: keep the existing screens, styling, payment page and matching contract working, keep ALL existing data usable, and migrate it as specified. Do NOT seed any fake/demo data, and do NOT change how payments are matched (the Cloudflare Worker still does that — this app only gains the account/store layer around it).

ACCOUNTS & OWNERSHIP MODEL (add exactly this)
- Firebase Authentication stays (Email/Password + Google), but sign-ups are now OPEN. A new account is a merchant account with planStatus "trial" and trialEndsAt = sign-up time + 7 days; after the trial the account is inactive (dashboard shows a clear Bangla "মেয়াদ শেষ" state, no new sessions) until the super admin activates it.
- The EXISTING owner account becomes the SUPER ADMIN: create its payAccounts doc with isSuperAdmin: true and planStatus: "active". Only the super admin sees the Super Admin panel.
- A merchant account owns one or more STORES. Every store has: name, type — "own" (the super admin's own shops) or "customer" — its own payment numbers, its own store key, and its own webhook URL + secret. For non-super-admin accounts the type is always "customer". The super admin's own stores use EXACTLY the same screens and flows as customer stores — do not build him a separate system.
- The super admin can: activate / suspend any account, set an account's paid-until date, CONVERT a store's type (own ↔ customer), and REASSIGN a store to a different owner account. Convert and reassign require a mandatory Bangla note and write a payActivity entry (who, what, from→to, note, when). A store's past sessions/SMS history is never deleted or moved by a convert/reassign — history stays with the store.
- SHARED ACCESS (members): a store has ONE primary owner (payStores.accountId) plus optional members stored as a memberRoles map { accountId: "co-owner" | "manager" | "viewer" } on the store doc. The primary owner (or the super admin) can add/remove members by account email. A co-owner can operate the store fully EXCEPT transferring ownership, deleting the store, or rotating the store key; a manager can view sessions/SMS and confirm payments manually; a viewer is read-only. TWO EQUAL primary owners are deliberately NOT supported — exactly one primary owner per store avoids key/ownership conflicts. The super admin always retains platform-level control over every store regardless of membership — that is his permanent copy of ownership.

DATA MIGRATION (do this in code, idempotently — running it twice must not duplicate anything)
- New collections: payAccounts/{accountId} { email, displayName, isSuperAdmin, planStatus: "trial"|"active"|"suspended", trialEndsAt, paidUntil: null, dailySessionCap: 200, createdAt }; payStores/{storeId} { accountId, name, type, numbers { bkash, nagad, rocket, upay }, numberEnabled, uniquePaisa, sessionMinutes, storeKeyHash, webhookUrl, webhookSecretSet, lastWebhook, createdAt }; payActivity/{entryId} { actorAccountId, action, targetType, targetId, detail, note, createdAt }.
- Migrate the existing paySettings/main into ONE store owned by the super admin: name = the stored storeName, type "own", numbers / number settings / uniquePaisa / sessionMinutes copied over; the existing store key becomes that store's key (keep accepting it — do not force a rotation); the stored workerBaseUrl moves to a platform config value the super admin can edit; lastWebhook moves to the store.
- Backfill accountId + storeId (the migrated store) onto every existing paySessions and payDevices document, and accountId onto every paySms document and usedTrxIds document, where missing. New sessions/SMS/devices are always written WITH accountId (and storeId where applicable) from now on.
- A device now belongs to an ACCOUNT (one phone serves all of that account's stores): payDevices gains accountId; pairing/revoke flows stay as they are, scoped to the signed-in account.
- Update the Firestore security rules: a signed-in user can read/write ONLY documents whose accountId equals their own uid; store members get access to their store's documents at their role's level (co-owner: read/write store data except key rotation and ownership actions; manager: read + manual-confirm; viewer: read-only); the super admin can read all payAccounts / payStores / payActivity (admin panel) but cannot edit another account's sessions/SMS; usedTrxIds stays Worker-only (no client access). Isolation must hold even if a user guesses another store's or session's ID.

DASHBOARD CHANGES (Bangla-first, same clean style, NO subtitles; everything scoped to the signed-in account)
- Add a store switcher at the top when the account has more than one store; Overview / লাইভ সেশন / SMS লগ operate on the selected store (SMS লগ is account-wide, filtered to the account).
- পেমেন্ট নম্বর becomes স্টোর সেটিংস per store: numbers + per-number on/off, uniquePaisa, sessionMinutes, payment-page branding (logo URL + accent colour), the store's webhook URL + secret (secret shown only as "সেট করা আছে" once saved, never plain text), store-key display with a rotate button (new key shown ONCE; rotating invalidates the old), last webhook result.
- New আমার স্টোরসমূহ screen: the account's stores with sessions today + paid today each, and "+ নতুন স্টোর" (name only; the rest is set in স্টোর সেটিংস).
- New অ্যাকাউন্ট screen: plan status + trial/paid-until dates, today's session count vs the daily cap, sign-out, and a CSV export of the selected store's paid sessions for a chosen date range.

SUPER ADMIN PANEL (new top-level section, visible only when isSuperAdmin)
- সব অ্যাকাউন্ট: table of payAccounts (email, name, plan chip, trial/paid-until, stores count, sessions today, joined). Actions per row: সক্রিয় করুন / স্থগিত করুন, মেয়াদ সেট করুন (paid-until date), daily cap edit — each with a Bangla confirmation and a payActivity entry.
- সব স্টোর: table of payStores (name, owner email, type chip নিজের/কাস্টমার, sessions today, paid today). Actions: type CONVERT (own ↔ customer) and মালিক বদলান (reassign — pick the new owner account from a list) — both with the mandatory note + activity-log entry.
- প্ল্যাটফর্ম সারাংশ: today's platform totals (sessions, paid amount, new accounts), a 7-day platform bar chart, and the latest 20 payActivity entries.

PAYMENT PAGE — behaviour stays, with two upgrades: (1) it now reads the STORE's name, logo and accent colour (new per-store branding fields in স্টোর সেটিংস: logoUrl, accentColor — sensible defaults when unset), and (2) REDIRECT-BACK like a payment gateway: a session may carry successUrl / failUrl (set by the integrating website when the session is created); when the session becomes confirmed the page shows the success state, then auto-redirects to successUrl after a few seconds with a visible "ফিরে যান" button for an immediate return (same for the fail/expired state with failUrl when present). With no URLs set, the page simply stays on its success/failure state as before.
